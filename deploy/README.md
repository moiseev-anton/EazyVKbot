# VK Callback API рядом с Telegram-ботом

Callback API — входящий webhook: ВК отправляет POST на сервер бота, а бот отвечает
через обычные методы VK API. Polling не используется. Развёртывание рассчитано на
один контейнер `vk-bot` в существующей Docker-сети `backend_net`, как у Telegram-бота.

## 1. Настройки на сервере

Скопируйте проект в отдельную папку. Сохраните существующие BOT_TOKEN, API_BASE_URL,
HMAC_SECRET, BASE_SCRAPING_URL и остальные настройки в `.env`.
Файл `.env` не входит в Docker-образ и передаётся Compose при запуске.

Добавьте:

```dotenv
BOT_MODE=callback
VK_CONFIRMATION_CODE=41fe4c87
VK_CALLBACK_SECRET=replace-with-random-secret
CALLBACK_PATH=/vk/callback
CALLBACK_PORT=8080
CALLBACK_HOST=0.0.0.0
```

Код подтверждения выше предоставлен для сообщества **224758825**. ID сообщества бот
получает по BOT_TOKEN и проверяет во всех входящих запросах. Используйте токен именно этого
сообщества с правом работы с сообщениями. Для другого сообщества нужен его код подтверждения.

Секрет придумайте отдельно от BOT_TOKEN и HMAC_SECRET. Например, сгенерируйте его локально:

```sh
python -c 'import secrets; print(secrets.token_hex(32))'
```

Одинаковое значение запишите в `.env` и поле «Секретный ключ» Callback API в ВК.
Секрет обязателен в этой реализации, включая проверочный запрос `confirmation`.

REDIS_STORAGE_URL должен указывать на доступный Redis в сети backend_net, а не
localhost контейнера. Например, `redis://redis:6379/1`, если существующий сервис
действительно называется `redis`. Сохраняйте пароль/номер БД вашей конфигурации.
Для очереди нужен Redis с сохранением данных на диск (AOF и постоянный volume);
не используйте политику вытеснения ключей для этой БД. Отдельный Redis в Compose не создаётся.
API_BASE_URL также должен быть доступен из контейнера.

Адрес callback задаётся в настройках сообщества; его путь должен совпадать с CALLBACK_PATH.

## 2. Контейнер и Nginx

```sh
docker network inspect backend_net
docker compose config --quiet
docker compose up -d --build
docker compose logs --tail=100 vk-bot
```

Compose задаёт callback-режим и слушает 0.0.0.0:8080 внутри контейнера.
На хосте порт доступен только по 127.0.0.1:9080. Healthcheck проверяет HTTP-сервер и Redis.

Добавьте `location` из [nginx-location.conf](nginx-location.conf) в существующий HTTPS
server-блок eazyclass.ru. Выберите одну строку proxy_pass:

- Nginx в контейнере сети backend_net: `http://vk-bot:8080`.
- Nginx на хосте: `http://127.0.0.1:9080`.

Сначала запустите vk-bot, затем проверьте конфигурацию Nginx (`nginx -t`) и перезагрузите
его конфигурацию. HTTPS-сертификат существующего сайта подходит; отдельный сертификат
в контейнере бота не нужен. Путь /vk/callback должен направляться в бот, не в SPA или Django.
Не ставьте на этот путь браузерную авторизацию или CSRF-проверку Django.

Если у Nginx включено кеширование upstream DNS, после пересоздания контейнера бота
перезагрузите Nginx, чтобы обновить адрес сервиса.

## 3. Настройки сообщества VK

В разделе «Работа с API → Callback API» добавьте сервер:

| Поле | Значение |
| --- | --- |
| Адрес | `https://eazyclass.ru/vk/callback` |
| Секретный ключ | Ровно значение VK_CALLBACK_SECRET |
| Строка подтверждения | В `.env`: VK_CONFIRMATION_CODE=41fe4c87 |

Сохраните секрет до подтверждения адреса. Нажмите «Подтвердить».
ВК отправит JSON с type=confirmation, group_id и настроенным secret.
Бот проверит ID/secret и вернёт HTTP 200 с телом `41fe4c87`: без JSON, кавычек или HTML.

После подтверждения включите события:

- `message_new` — входящие сообщения и постоянные текстовые кнопки;
- `message_event` — нажатия inline callback-кнопок.

Для структуры событий, используемой текущим SDK, выбирайте версию API 5.199, если она
доступна в настройках. Возможности ботов и сообщения сообщества должны быть включены.
Остановите локальный polling-процесс этого же бота и отключите его Long Poll-доставку:
одновременный polling и callback могут обработать действие дважды.

## 4. Проверка

На сервере `curl http://127.0.0.1:9080/healthz` должен вернуть `ok`.
GET публичного /vk/callback не является проверкой: endpoint принимает POST и вернёт 405 на GET.
POST без правильного секрета возвращает 403 — это ожидаемо.

В ВК проверьте «Главная», выбор группы, расписание, inline-стрелки и авторизацию.
В журнале Callback API нормальные события должны получать HTTP 200 с телом `ok`.

Если подтверждение не проходит:

- 403: несовпадение secret или токен другого сообщества;
- 404/HTML: путь попал в другой location/SPA;
- 502: Nginx не видит контейнер или бот не запустился;
- 503 на событии: Redis недоступен, событие не принято, ВК может повторить доставку.

## Доставка и ограничения

Событие записывается в Redis Stream до ответа `ok`. Повторный event_id не ставится в очередь
повторно в течение 24 часов. Callback-secret удаляется перед сохранением события.
Один последовательный worker читает события, в том числе незавершённые после перезапуска.
После обработки запись удаляется. Не запускайте несколько экземпляров этого worker.

Это не гарантия exactly-once: аварийная остановка между внешним действием и подтверждением
обработки может привести к повтору. Бизнес-ошибки, которые контроллер обработал сообщением
пользователю, автоматически не повторяются. При накоплении очереди ответы будут задерживаться;
проверяйте логи и длину `vkbot:224758825:callback:inbox`.

Локальные автоматические тесты проверяют HTTP endpoint, секрет, подтверждение, передачу событий
в очередь и восстановление worker с подставным Redis. Реальное подтверждение в VK и работу
инфраструктуры необходимо проверить после размещения на сервере.
