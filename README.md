# EazyClass VK bot

VK-версия основных сценариев EazyBot. Python 3.12+, Redis и существующий JSON:API backend EazyClass.

Зависимости проверены и обновлены 10.10.2026: vkbottle 4.11.0, vkbottle-types 5.199.99.22,
aiohttp 3.14.4, Pydantic 2.14.0, pydantic-settings 2.15.0 и redis-py 8.1.0.
`aiofiles==24.1.0` сохранён из-за точного ограничения vkbottle; jsonapi-client 0.9.10
остаётся последним доступным релизом. `requirements.txt` фиксирует прямые зависимости,
а `requirements.lock.txt` — полный проверенный набор, включая транзитивные зависимости.
Для воспроизводимой установки используйте `python -m pip install -r requirements.lock.txt`.

Код проверяется по установленному API vkbottle 4.11, включая `process_event` и асинхронный
Long Poll. Сохранён собственный цикл обработки пакетов, чтобы дождаться завершения обработчиков
перед закрытием Redis и HTTP-сессий. Устаревшие `LoopWrapper` и `run_forever` не используются.
Новая версия SDK хранит позицию Long Poll в `.vkbottle/`; эта служебная папка исключена из Git.

## Реализовано

- Регистрация VK-аккаунта через `/auth/`, подтверждение входа на сайт через `/auth-with-nonce/`.
- Постоянная клавиатура: главная, сайт, авторизация.
- На главной кнопка «Расписание» доступна при наличии подписки; в карточках групп и преподавателей она открывает тот же экран расписания. Выбор периода находится внутри расписания.
- Inline-меню: факультет → курс → группа; буква фамилии → преподаватель.
- Режимы расписания «Сегодня» и «Неделя»; листание периодов стрелками, страниц и обновление.
- День недели и дата выделяются жирным через VK `format_data` при отправке и редактировании расписания; смещения учитывают UTF-16 и эмодзи.
- Подписка, подтверждение замены существующей подписки, отписка.
- Настройки уведомлений о предстоящих занятиях и изменениях расписания, отписка от текущей подписки.
- Redis-состояние с TTL, проверка устаревших кнопок и блокировка одновременных действий пользователя.

Текстовое представление сохраняет время, аудиторию, предмет, примечание, часть занятия, подгруппу и преподавателя/группу. Длинное расписание разбивается на страницы. Rich-блоки Telegram не используются.

В меню выбора названия показаны только на кнопках; преподаватели везде отображаются через `short_name`.
Списки до восьми вариантов помещаются на одну страницу, более длинные показываются по шесть:
остальные места отведены навигации в пределах десяти inline-кнопок. Дни расписания отделены
текстовыми заголовками, занятия — пустыми строками. Периоды переключаются стрелками.

Текст «Начать» или `/start` сбрасывает историю меню и ожидающее
подтверждение входа, сохраняя подписку. Процесс бота не перезапускается.
Команды постоянной панели отправляют одно сообщение с содержимым экрана, затем добавляют
к нему inline-кнопки редактированием. Сохранение постоянной панели после такого редактирования
нужно проверить в используемых клиентах VK.

## Запуск

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
Copy-Item env.example .env
# Заполнить .env и запустить Redis по REDIS_STORAGE_URL.
.venv/Scripts/python.exe bot.py
```

Не перезаписывайте существующий `.env`: добавьте недостающие настройки вручную. Альтернативная точка входа: `python -m vkbot`. Поддерживаются `BOT_MODE=polling` и `BOT_MODE=callback`. Для деплоя рядом с Telegram-ботом см. [deploy/README.md](deploy/README.md).

Обязательные настройки:

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | Токен сообщества с доступом к сообщениям |
| `API_BASE_URL` | URL JSON:API backend |
| `HMAC_SECRET` | Общий с backend секрет подписи |
| `BASE_SCRAPING_URL` | Адрес сайта расписания, историческое имя из Telegram |
| `REDIS_STORAGE_URL` | Redis, по умолчанию `redis://localhost:6379/1` |
| `STORAGE_STATE_TTL` | Срок хранения меню в секундах, по умолчанию 3600 |
| `AUTH_NONCE_TTL` | Локальный срок ожидания подтверждения, по умолчанию 300 |
| `SCHEDULE_TIMEZONE` | Часовой пояс расписания, по умолчанию `Europe/Moscow` |
| `SHOW_ENTITY_LINKS` | `true` показывает ссылку на страницу группы/преподавателя, `false` скрывает; по умолчанию `true`. Применяется после перезапуска бота; кнопка «Сайт» остаётся доступной |

В сообществе нужно включить сообщения и возможности ботов. В выбранном транспорте (Long Poll API или Callback API) включите события `message_new` и `message_event`. Состояния разделены по ID сообщества и пользователя. Справочники обновляются по запросу не чаще раза в 10 минут.

## Вход с сайта

1. Сайт создаёт случайный одноразовый nonce, связанный с браузерной сессией, и открывает `https://vk.me/<community>?ref=<nonce>`.
2. Пользователь отправляет сообщение: кнопкой начала диалога, постоянной текстовой кнопкой авторизации или вручную.
3. Бот сохраняет полученный `ref` в Redis. Если пользователь нажал «Начать» или «Начать авторизацию», вход подтверждается сразу. Для произвольного сообщения или другой команды бот предлагает отдельную кнопку подтверждения. Новый `ref` имеет приоритет над ранее сохранённым nonce.
4. Подтверждение передаёт nonce вместе с VK ID и chat ID в backend. Успех показывается только при `nonceStatus=authenticated`.
5. После ответа backend nonce удаляется локально; при сетевой ошибке можно повторить подтверждение до истечения TTL. Отмена удаляет ожидающий nonce.

Кнопка авторизации без сохранённого nonce генерирует случайный UUID v4 через
`str(uuid4())`, совместимый с `UUIDField` backend, и отправляет его на `/auth-with-nonce/`. Только при
`nonceStatus=authenticated` бот возвращает сообщение «Авторизация прошла успешно, нажмите кнопку для входа»
и кнопку «Войти» со ссылкой `https://eazyclass.ru/schedule?nonce=...`. Дополнительное главное меню
не отправляется. SPA должна прочитать параметр и обменять nonce на JWT через существующий backend.
Срок действия nonce определяется backend. Сгенерированный nonce не сохраняется как ожидающий
подтверждения в Redis; повторное нажатие создаёт новый. При наличии nonce с сайта работает прежний сценарий.

Backend обязан проверять срок действия и одноразовость nonce, привязку к сессии, платформу `vk` и HMAC. Локальный TTL этого не заменяет. Нельзя рассчитывать, что открытие ссылки само отправит сообщение. Доставку `ref` необходимо проверить на используемых клиентах VK.

## Проверка

```powershell
.venv/Scripts/python.exe -m unittest discover -s tests -v
```

Автоматические проверки используют подставные VK/backend API и Redis; реальные сообщения не отправляются. Проверяется также маршрутизация через установленный vkbottle.

Перед эксплуатацией провести живую проверку:

- Первый и повторный вход через браузер и мобильный VK, отсутствие и истечение `ref`, отмена и повторное использование nonce.
- Создание VK-аккаунта и проверка backend HMAC; получение настроек и подписок.
- Группа и преподаватель, длинные списки, пустое и длинное расписание.
- Атомарная замена подписки на backend. Бот вызывает тот же POST, что Telegram, и не удаляет старую подписку отдельным запросом.
- Возврат после перезапуска бота, старые кнопки и запрет сообщений сообщества.

## Границы текущей реализации

Настройки уведомлений сохраняются в backend. Сам отправляющий сервис отсутствует в обоих предоставленных репозиториях: автоматическая рассылка напоминаний и изменений этим процессом не выполняется. Для неё нужен отдельный этап интеграции с источником событий и проверкой разрешения сообщений VK.

Доступ к реальному backend, Redis и сообществу не входит в изолированные тесты. Настройки и токены Telegram не изменяются.
